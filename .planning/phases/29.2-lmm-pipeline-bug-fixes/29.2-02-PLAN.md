  <name>Task 1: Fix eigen file validation to use covariate-filtered sample count</name>
  <files>src/jamma/pipeline.py</files>
  <action>
In `PipelineRunner.run()`, the standard path (non-LOCO) loads eigen files at step 7 (line 529) using `n_analyzed` (phenotype-only count), but covariates are loaded at step 8 (line 571). The runner then further filters by covariate NaN, meaning the actual valid sample count can be smaller than `n_analyzed`.

Fix: Move covariate loading BEFORE the eigen file validation step. Restructure the standard path as follows:

1. After step 4 (phenotypes, line 455), load covariates EARLY (currently step 8):
```python
# 5. Covariates (loaded early for eigen validation)
covariates = self.load_covariates(n_samples)
```

2. Compute the covariate-aware valid sample count:
```python
# Compute valid sample count (phenotype + covariate filtering)
valid_mask = ~np.isnan(phenotypes) & (phenotypes != -9.0)
if covariates is not None:
    valid_covariate = np.all(~np.isnan(covariates), axis=1)
    valid_mask = valid_mask & valid_covariate
n_valid = int(np.sum(valid_mask))
```

3. Use `n_valid` instead of `n_analyzed` when calling `read_eigen_files`:
```python
eigenvalues, eigenvectors = read_eigen_files(
    self.config.eigenvalue_file,
    self.config.eigenvector_file,
    n_samples=n_valid,  # Covariate-aware count
)
```

4. Also fix the `write_eigen` path (line 554): the existing `valid_mask` there only checks phenotype NaN. Update it to also include covariate NaN filtering so the written eigen files are consistent with what the runner will use:
```python
if self.config.write_eigen:
    # valid_mask already includes covariate filtering from above
    K_valid = K if np.all(valid_mask) else K[np.ix_(valid_mask, valid_mask)]
```

5. Remove the duplicate covariate loading at the old step 8 location (currently line 571) since covariates are now loaded earlier. Keep the `load_s` timing calculation but adjust it.

**IMPORTANT:** The LOCO branch (line 487) already loads covariates independently and passes them to `run_lmm_loco`, which computes its own valid_mask. Do NOT change the LOCO branch.

**IMPORTANT:** The `n_analyzed` variable (phenotype-only count) is still needed for the log message at line 457 and for `PipelineResult.n_samples`. Keep it. Only the eigen validation uses `n_valid`.
